# Источник значений для enum'ов контракта

Контракт заводит **свои** backed string enum'ы (`AnimeType`, `Demographic`,
`GenreCode`, `ThemeCode`, `SyncStatus` и т.п.) для полей, которые являются
закрытыми словарями — вместо `string`, чтобы не терять типобезопасность,
но и не тянуть зависимость на хост-приложение (см. `MUST NOT` в
`CLAUDE.md`).

Значения этих enum'ов должны совпадать 1:1 с одноимёнными enum'ами
хост-приложения, но проверить это, не имея доступа к репозиторию хоста в
текущем окружении, не выйдет — `anime-db-plugin-contracts` не содержит
исходников хоста.

Хост-приложение (desktop) в рабочем окружении лежит в отдельном чекауте:

```
/var/www/anime-db-workspace/docs/anime-db-desktop/app/src/Entity/Enum/
```

Перед тем как заводить/менять enum контракта под значения хоста —
свериться с исходником там (например, `AnimeType.php`, `Demographic.php`,
`GenreCode.php`, `ThemeCode.php`), а не гадать/брать из внешних
источников (типа стандартной таксономии MAL) — они могут разойтись.

# ManifestValidator намеренно не отвергает незнакомые поля манифеста

`ManifestValidator::validate()` не проверяет манифест на строгое
соответствие фиксированной схеме — он отвергает только известные-но-
неуместные для данного `type` поля (`features` у `PluginType::Translation`,
`locales` у `PluginType::Integration`, см. `validateFeaturesOrLocales()`),
а не любой ключ вне списка, который знает пакет.

Причина: схема `manifest.json` расширяется потребителями за пределами
этого контракта. Пример — `translation_keys_count`: поле реестра маркета,
обязательное для манифестов типа `translation`, валидируется тулингом
монорепозитория плагинов (сверкой с фактическим содержимым
`translations/`). В `Manifest` DTO оно не заводится и этим пакетом не
проверяется — манифест с ним просто проходит валидацию как есть.

**Не превращайте это в «однострочную гигиеническую правку».** Ужесточение
`ManifestValidator` до строгой схемы (отвергать любое поле вне
перечисленных) отвергнет все манифесты плагинов-переводов, у которых
`translation_keys_count` обязателен. Дальше по цепочке — красные PR в
монорепозитории плагинов и падение установки плагина в хост-приложении на
валидации манифеста, причём причина будет выглядеть как поломка на
стороне плагинов, а не как следствие правки в контракте.

См. также раздел README «Незнакомые поля манифеста» (описание для автора
плагина) и `MUST NOT` в `CLAUDE.md`.
